## Block Recipes

- Reworked `Block/@Block` infrastructure to support Block recipes. Analogously to `@recipe` a Block recipe allows you to define a new block using existing blocks. For this the new block acts like a GridLayout that will later be added to a figure `MyBlock(fig[1, 1])`. A block recipe may also include plots, e.g. to an `Axis` created within the recipe.
- Added support for `@recipe`-like arguments in Blocks with `@Block MyBlock (arg1::Vector, arg2)`
- Added support for argument conversions in Blocks with `convert_arguments(::Type{MyBlock}, args...)`
- Added support for Block conversion traits with `conversion_trait(::Type{MyBlock})`
- `Makie.initialize_block!(b::MyBlock)` can now be used analogously to `Makie.plot!(p::MyPlot)`. The given parent block can be indexed like a figure/GridLayout, e.g. `Axis(b[1, 1])` works.
- Added `block.layout`, `block.blocks` and `block[i, j]` for accessing the blocks inside a block recipe. Note that these require `initialize_block!(block)` to add blocks or call `Makie.init_layout!(block)`.
- Note: Type-based conversions of attributes still rely on `Makie.convert_for_attribute(::Type{T}, user_input)`.
- Note: Attributes within a `@Block` are defined in a separate `@attributes begin ... end` section. This is needed because `@Block` supports adding fields in the main scope.
